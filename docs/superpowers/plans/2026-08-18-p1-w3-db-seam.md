# P1 W3 批次1：db seam + db-opengauss + tool-db 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans（本计划在会话内直接执行）。

**Goal:** agent 在对话里能对其绑定的 openGauss 节点执行只读诊断（db_nodes / db_query / db_overview 三个工具）。

**Architecture:** `@opendb-dsh/db` 提供 `opendbDb` 服务（每节点连接池 + 只读三层防护 + 方言注册表，内置 postgresql 基线方言）；`@opendb-dsh/db-opengauss` 注册 og 方言（dbe_perf.* 视图）；`@opendb-dsh/tool-db` 向 Runtime 的 tools 注册表注册三个模型工具，agent 归属经 `exec.agent` 的 cwd 解析（同 instructions-pg），查询范围限定该 agent 绑定的节点。

**Tech Stack:** node pg（已验证 MD5 直连 og 5.0.3）、schemastery、dsh-tools defineTool。

**Spec:** docs/2026-08-16-opendb-dsh-platform-design.md §8（db seam）；P0/W1 计划同目录。

## Global Constraints
- 凭据不落库（003_registry.sql 既有决策）：`OPENDB_DB_CREDENTIALS` env = JSON `{ "<node名>": {"username","password"} }`，k8s Secret `opendb-db-credentials` 注入，lab 外换 vault。
- 只读三层防护：SQL 语法门（tool-db guard）→ 连接级 `SET default_transaction_read_only=on`（db 服务）→ 账号级 `opendb_ro` MONADMIN + default read-only（og 侧，已建好）。
- 行数上限 200 / statement_timeout 15s / 输出超限交给 spill-s3。

## 已验证前提（2026-08-18 og5 探针）
- node pg 驱动 MD5 直连 og-lite 5.0.3 ✅（password_encryption_type=1 + pg_hba md5）
- MONADMIN 账号可读 dbe_perf.instance_time / statement、pg_stat_activity ✅
- default_transaction_read_only=on → 写被 25006 拒绝 ✅

- 测试：guard 判定表（允许 select/with/show/explain/values；拒绝多语句、写词、CTE 内 DML）；方言注册/回退；凭据 JSON 解析。

### Task 2: @opendb-dsh/db-opengauss（og 方言）
- Create: packages/db-opengauss/src/index.ts
- overview 查询组：version / sessions(pg_stat_activity) / instance_time(dbe_perf) / top_sql(dbe_perf.statement) / wait_events(dbe_perf) / locks / db_size / replication。
- 全组 SQL 先用 og5 探针跑通再定稿（列名以 og-lite 5.0.3 实测为准）。

### Task 3: @opendb-dsh/tool-db（三个模型工具）
- Create: packages/tool-db/src/{index,agent,render}.ts
- db_nodes：列当前 agent 绑定节点；db_query{node?,sql,max_rows?}：guard→query；db_overview{node?}：方言组查询。节点默认取 agent 唯一绑定节点，多节点必须点名，未绑定报错。
- 注册方式：`anyCtx.inject(['tools'], c => c.effect(() => c.tools.register(...)))`（同 spill-s3）。
