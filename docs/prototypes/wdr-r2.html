根因串联与处置优先级 模型解读 · 引用的数字均有出处

根因串联
窗口负载由 3 条 fact_sales 的 query_dop=1 强制串行大聚合主导（share 合计 94%）。跨维度互证：① 命中率 93.56% 与串行全表大扫描互证——物理读 2.02M 块、上窗只有 1.24M；② 临时文件 18.4 GB 与哈希聚合下盘互证——Top1 SQL 是窗口内唯一有显著 hash_spill 的语句，等待事件里 BufFileWrite/Read 合计 327 s 正是下盘的读写；③ 主机 CPU 忙 18%、iowait 0.07%、TPS 与上窗持平——瓶颈在分析型 SQL 的执行方式，不在硬件或 OLTP。
处置优先级
P1
三条串行聚合放开 query_dop（Top SQL 报表已实证同口径 cost 降 30–46%），或改汇总表——直接消掉 94% 的窗口耗时 1136765424 1478806352 69381302
P2
哈希聚合下盘：评估 work_mem / hash_mem 对这三条语句的会话级调优（只读平台不代改，给出参数建议） WDR_TEMP_SPILL
P3
命中率随 P1 消化；若仍低于 95%，再看 shared_buffers 与冷数据扫描策略 WDR_CACHE_LOW
