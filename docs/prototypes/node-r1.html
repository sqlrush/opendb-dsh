设计说明（给确认用，实现时不出现）

  1. 信息架构：页头（身份 + 综合结论）→ 现在（8 项数据库 KPI + 4 项 OS 层：CPU 忙 / 负载 / 内存 / IO 等待，阈值着色，24h 迷你曲线）→ DB Time 构成 / 主机资源明细 → 五类巡检最近结论（每类一卡：级别 · 一句话 · 2–3 个关键数 · 计划/逾期 · 查看报告）→ 存储与增长 / 变更时间轴 → 本节点定时任务 → 关于这个库平台记住了什么。
  2. 确定性直读：所有数字来自 opendb_metrics（37 条序列，1 分钟）、opendb_task_collects（五类存档）、opendb_health_collects、opendb_capacity_samples、dsh_tasks / dsh_task_runs / dsh_task_reports、字典变更；模型报告只贡献"一句话"。TPS/QPS/命中率由计数器差分得到，不再展示累计原值。
  3. 综合结论算法：取五类"最近结论"中最差档；超过各自时效窗口（cron 周期 ×2，手动任务 7 天）的结论灰显并不进综合，避免 6 天前的实验库 DDL 把整页染红。
  4. 逾期：按 cron 应触发而未触发的任务显式标出（现在 og5 有 4 个每小时/每日任务停在 08-29，这是真数据暴露的问题，另行处理）。
  5. 变更时间轴：字典变更按"同一秒 / 同一 schema"折叠成批次，异常批次带 DDL 审计或事故响应的判定与链接；不再铺几十行原始表。
  6. 零按钮：整页只有「在会话里深挖 →」「查看报告 →」两种文字链（沿用 task-health 的 DigLink，带"开会话中… / 失败，重试"三态）与页内文字 tab（24 小时 / 7 天）。
  7. 样式：dsh 原版 token（主蓝 #4176E6、灰阶 chrome、语义色只上数据、卡片 12px 圆角 + 双层浅影）；内容区字号体系（16 正文 / 18–24 区块题 / 13.5 meta / 13 mono）；图表全部 chart-kit 自绘 SVG，不引第三方。
  8. 空态与降级：某类巡检从未跑过 → 该卡显示「还没跑过 · 在会话里说一句就能建」；采集缺项（如已用内存）→ 明说"未采集"并给补采集链接，不留假 0。
  9. OS 层补采集（重构时一并做）：现有 db.os.* 只有 CPU 时间片 / 负载 / 核数 / 物理内存总量 / IO 等待时间。新增 db.mem.process_used_bytes 与 db.mem.max_process_bytes（来源 gs_total_memory_detail），内存卡位才有真曲线；磁盘吞吐与网络流量 openGauss 视图不提供，不做假数。CPU 忙 % = (user+sys+iowait) 时间片差分 / (总时间片差分)。
  10. 实现落点：重构 ui-node-monitor 客户端 + 扩 ui-opendb 的 nodes/detail（新增 rates / dbTime / os / verdicts / capacity / tasks / timeline / knowledge 分区，一次 RPC 出全页）；行为测试 scripts/browser/node-panel-check.mjs。
