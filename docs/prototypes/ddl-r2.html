变更故事线
这 35 天里 og5 的结构变化是三代基准库的演进：07-28 建第一代 gsbench（17 表，单列主键、无分布键）；07-29 建 gsbench_v4（33 表：所有事实/明细表加 dist_key 并改为 (dist_key, id) 复合主键，新增 ddl_global_*、dist_*、network_ingress、sort_data 等 16 张场景表，当天下午两次调整 plan_data 索引与 meta_* 缓存表）；08-02 建 gsbench_e2e_20260801_100g（在 v4 基础上把 plan_data 的 shape_bad 索引换成 shape_good + 补 index_drop 索引，lookup 索引移到 pg_default 表空间）。之后是三次运维动作：08-18 平台探针表 w3_dict_probe 建后即删（DDLR01，属平台自检）；08-24 09:33 对 gsbench / e2e 两个 schema 的 51 张表批量授权（对应 08-23 补授只读账号读权）；08-26 14:31 e2e 新增 vacuum_hold_targets 并微调 plan_data 索引，21 分钟后再改一次。账号面 4 次变更都是 omm 对平台账号 opendb_ro 的授权演进（MONADMIN → 只读 → AUDITADMIN → SYSADMIN）。没有业务表被删或被截断。
